## 재발 방지 메모 (계속 유효)

**MCP는 세션 시작 시점에 한 번만 붙는다.** 세션이 열린 뒤 에디터를 켜면 그 세션에는 안 붙고,
`--continue`로도 복구되지 않는다(세션 상태를 그대로 복원). **에디터를 먼저 띄운 뒤 새 세션을 열 것.**

**우회로는 없다 — 2026-09-09에 둘 다 막힌 것을 실측했다.**

| 시도 | 결과 |
|---|---|
| Claude Code 서브에이전트(`qa-quick-check`)에 위임 | ❌ **메인 세션의 MCP 연결 상태를 그대로 공유한다.** 새 프로세스가 아니라서 똑같이 `ConnectionRefused` |
| `codex exec --sandbox read-only`에 위임 | ⚠️ **MCP 연결 자체는 된다**(인스턴스·Unity 버전·Play Mode 상태까지 읽어옴). 그러나 `refresh_unity` 같은 **조작 도구는 `MCP tool call requires approval, but approval policy is never`로 거부**된다 — `exec`는 비대화형이라 승인을 받을 방법이 없다 |

→ 읽기(에디터 상태 조회)만 필요하면 `codex exec`가 쓸 만하다.
**리임포트·재컴파일·Play Mode처럼 조작이 필요하면 새 세션 외에 길이 없다.**
그러니 에디터 검증이 걸린 작업은 **시작 전에** 에디터부터 띄운다.

**2026-09-10 보강 — 아직 안 막힌 길이 두 개 있다.**
1. **대화형 Codex 세션에서는 된다.** 승인 프롬프트가 떠서 사용자가 허용할 수 있다.
   막힌 건 "비대화형 `codex exec`"뿐이다. 사용자가 QA를 Codex에 맡기고 싶어 하므로
   (2026-09-10 지시), QA 브리프 파일을 만들어 경로를 넘기고 Codex 세션에서 돌리는 방식이 정석이다.
2. `codex exec --approve-for-me` — 승인 요청을 자동 심사로 라우팅하는 옵션이 존재한다(**미검증**).
   시험하려면 에디터가 놀고 있을 때 `refresh_unity` 호출로 1회 확인한다.
   단 이 옵션은 workspace-write 샌드박스를 쓴다고 돼 있어, 통하더라도
   `AGENT.MD`의 "codex exec는 읽기 전용" 계약과 충돌하는지 따로 판단해야 한다.

**콘솔 로그 조회(`read_console`)가 로그를 못 가져오는 경우가 있다.** 2026-08-27에
`Debug.Log`를 직접 호출해도 0건으로 나왔다. 로그가 안 보인다고 "그 코드가 안 불렸다"고
판단하면 엉뚱한 곳을 파게 된다 — 호출 여부를 봐야 하면 **관측 가능한 상태(카운터 등)로 확인할 것.**
