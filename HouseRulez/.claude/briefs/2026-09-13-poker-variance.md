# 포커 하방 보강 — 수치 확정 실측

## 배경

2026-09-13 밸런스 표본(`D:/Orca/reports/balance-sample-2026-09-13.md`)에서
**Poker 1-3 코인소진 / Chess 12-1 / Yut 12-3**이 나왔다. Codex가 "seed 운인지 구조적 약세인지
분리하려면 Poker 반복 표본이 우선"이라고 남겼고, Claude가 계산으로 그것을 갈랐다.

## 확정된 진단 (실측 불필요 — 계산으로 닫혔다)

### 1. Poker 약세는 구조다. 다만 GDD가 의도한 구조다

GDD 05장이 "평균 전력은 붙이고 **분산은 벌어지도록** 역산"했다고 명시한다.
Claude가 실제 판정 로직으로 20만 회를 돌린 결과가 **GDD 50만 회 표와 소수점까지 일치**했다.

| 종족 | 평균 | 표준편차 | 변동계수 | 무소환률 |
|---|---:|---:|---:|---:|
| chess | 6.11 | 3.90 | 0.64 | 0.5% |
| poker | 6.27 | 10.15 | 1.62 | 8.9% |

즉 **구현이 기획을 정확히 옮겼다.** 계수를 고치는 것은 GDD가 명시적으로 금지한다 —
"여기에 안전장치를 달면 포커의 정체성이 사라집니다."

### 2. 그런데 GDD의 완충 논증이 잘못된 지표를 썼다

GDD는 "연차당 스핀 3회가 완충이다, 3회 모두 빈손일 확률은 0.07%"라고 논증한다.
**실제 실패 모드는 빈손이 아니라 「적 전력 미달」이다.**

| | chess | poker |
|---|---:|---:|
| 완전 빈손(전력 0) | 0.5% | 8.9% ← GDD가 쓴 지표 |
| **1-1 적 전력(3.6) 미달** | 19.6% | **68.8%** |
| **3스핀 연속 미달** | 0.76% | **32.6%** |
| 중앙값 전력 | 5.20 | **2.00** |

포커의 전형적 스핀은 전력 2로, 1-1 적 3.6에도 못 미친다.
**Poker 1연차 종료는 32.6% 확률의 사건이고 chess는 0.76%다 — 43배 차이.**

### 3. 하방 보호 장치가 하방에서 작동하지 않는다

추가 스핀(`ExtraSpinGoldCost 25`, `ExtraSpinMaxPerYear 2`)이 이미 안전망이다.
그런데 골드는 판정 전력 비례(`GoldPerPower 2`)다.

- poker 중앙값 전력 2 -> 스핀당 골드 4 -> 25 모으려면 6~7스핀. **코인은 5개.**
- chess 중앙값 5.2 -> 스핀당 10.4 -> 2~3스핀에 구매 가능

실측 Poker 런의 최종 골드가 **20**(가격 25에 5 부족)이었고 Codex가 "추가 스핀 구매 조건도
충족하지 못해 닫혔다"고 기록했다 — 계산과 실측이 맞는다.

**즉 구제 수단의 가격이 상방 성과에 연동되어, 필요한 쪽이 살 수 없다.**

## 이번에 측정할 것

사용자 결정(2026-09-13): **분산은 GDD대로 지키고 패배를 버틸 능력만 올린다.**
판정 계수(`JudgeTable.csv`)는 건드리지 않는다.

### 1순위 — `RunStartGold` 0 -> 25 의 효과

`GameConfigTable.csv`의 `RunStartGold` 한 줄이다. 이유:

- 시작 골드가 0이면 **1연차에는 추가 스핀을 살 방법이 원리적으로 없다**(골드를 먼저 벌어야 함).
  그 1연차가 포커가 죽는 구간이다.
- 후반에는 골드가 충분히 쌓여 영향이 미미하다 -> 부작용이 작다.

측정: **Poker 원칙 A 5런 이상.** 1연차 종료가 몇 번인지가 답이다(기대: 32.6% -> 유의하게 감소).
Chess 2런으로 상방이 망가지지 않았는지만 확인한다.

### 2순위 — 대안과 비교

1순위가 부족하면 `ExtraSpinGoldCost` 25 -> 12 를 같은 방식으로 측정한다.
둘을 동시에 바꾸지 말 것 — 어느 것이 효과였는지 못 가린다.

## Claude 가 폐기한 것 — 같은 실수를 반복하지 말 것

런 전체를 시뮬레이션해 조정안별 종료 연차를 예측하려 했고 **실패했다.**
전투 승패를 "전장 전력 >= 적 목표 전력"으로 근사했는데 틀렸다.

- 전장 9칸 최대 전력은 **63.0**(3성 9기)인데 10-3 적 목표 전력이 **69**, 12-3은 **110.4**다.
  근사대로면 10연차에서 물리적으로 막히는데 **실측 Chess는 12-1(적 81.6)까지 갔다.**
- 원인: 3성 1기는 `Hp70/Atk14`, grunt 7마리는 각 `Hp10/Atk2`로 전력 지표는 같은 7이지만
  **동시 교전 수가 제한되므로 집중된 스탯이 분산된 스탯을 이긴다.**

**그래서 전투는 근사하지 말고 실제 `UIInGameBattle`을 돌려야 한다.**

### 별건 — 기록만 해두고 이번에 손대지 말 것

위 사실은 `WaveTable`의 **「PowerCoef -> 마릿수 역산」계약이 실제 난이도를 반영하지 못한다**는
뜻이다. 같은 목표 전력을 1마리로 주는지 7마리로 주는지에 따라 체감 난이도가 갈린다.
이번 측정 범위가 아니므로 관찰되면 보고서에만 남겨 달라.
