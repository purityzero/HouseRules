## 왜 다시 재는가

2026-09-13 이후 세 가지가 들어갔다.

| 변경 | 효과 |
|---|---|
| `RunStartGold` 0 → **25** | 1연차에 추가 스핀을 살 수 있게 됐다. Poker 1연차 종료가 8런 0/8(p=0.043) |
| 스왑 노드 → **추가 스핀 상한** | `swap` Lv3을 산 종족은 상한이 2 → **5**. **아직 런으로 측정 안 됨** |
| 드래그 배치 | 플레이어가 전장 칸을 바꿀 수 있다. **자동 배치로만 측정해 왔다** |

기획서 12장 관문이 **"아무 코어 없이 12연차 클리어율 20~35%"**인데
2026-09-13 실측은 **도달 8/10, 클리어 0/10**이었다. 전부 12연차 안에서 코인 소진이거나 함락.

## 이번 측정의 질문 둘

1. **지금 12연차를 클리어하는가** — 상한 5가 붙은 종족에서 특히
2. **열 배치가 그것을 바꾸는가** — 드래그의 실전 가치

## 측정 설계 — 같은 seed 로 A/B

**조건 A (자동 배치)** — 지금 그대로. `FillEmptyFieldFromBench()`가 빈 칸을 성급 높은 순으로 채운다.
열(깊이) 구분은 없다.

**조건 B (열 배치)** — A 위에 **열 재배치를 얹는다.** 매 스핀 뒤 · 전투 시작 전에
`RunRoster.SwapField()`로 전장 9칸의 깊이를 바꾼다.

```
Role 점수: Front=2, Mid=1, Back=0   (UnitTable.GetRecord(houseKey, symbolIndex).Role)
점수 내림차순으로 column 2 -> 1 -> 0 순서로 채운다.
  column 2 = cell 2,5,8  (가장 오른쪽 = 적과 가깝다)
  column 1 = cell 1,4,7
  column 0 = cell 0,3,6
같은 점수 안에서는 기존 순서를 유지한다(성급 배치는 이미 A가 정했다. 열만 바꾼다).
```

**같은 seed 로 A와 B를 각각 돌려야 비교가 성립한다.** 다른 seed면 분산에 묻힌다.

### 종족과 횟수

**Chess · Yut · Poker** 각 조건당 2런 = 12런이 목표. 시간이 모자라면 **종족당 1런씩(6런)** 으로 줄이고,
그 경우 Chess 를 우선한다(상한 5이고 이전 측정에서 12-1까지 갔다).

seed 는 이전과 겹치지 않게 `92401` 부터 순서대로.

원칙 A(웨이브당 스핀 1회, 패배 재시도에만 추가 스핀)는 이전과 동일하게 유지한다.

## ★ 기대를 과대평가하지 말 것

열 배치의 이득은 **크지 않을 수 있다.** 근거:

- `Role` 별 평균 배율 차이가 작다 — `AtkRate` 는 Front 0.926 / Back 1.105 로 19% 차이지만
  `HpRate` 는 Front 1.010 / Back 1.024 로 **오히려 Back 이 높다.** Hp/Atk 비로만 갈린다
  (Front 1.091 / Mid 0.931 / Back 0.926)
- `RangeBonus` 는 대부분 0이다(Back 11기 합계가 4)
- 예전 시뮬레이션의 "배치만 바꿔 전력 25 → 49"는 **성급 배치**였고 **그 이득은 이미 A 가 취하고 있다.**
  열 배치는 그 위의 추가분이다

**차이가 없게 나와도 그것이 결과다.** 없으면 드래그의 가치가 열 배치가 아니라 다른 데 있다는 뜻이고
(예: 플레이어 주도권), 그것도 알아야 할 사실이다.

## 전투가 실제로 열을 읽는가 — 먼저 확인할 것

`UIInGameBattle.SpawnAllies` 가 `column` 을 `m_AllyStartX + column * 108f` 로 쓰므로
**column 이 클수록 적과 가깝다.** 그리고 `FindTarget` 은 레인 제약 없이 2D 거리로 가장 가까운 적을 고른다.

즉 **앞 열 유닛이 먼저 맞는다**는 것이 이 측정의 전제다. B 조건을 돌리기 전에
간단히 한 번 확인해 달라 — 전투 시작 직후 적이 처음 공격한 아군이 column 2 에 있는가.
전제가 틀리면 열 배치 자체가 무의미하므로 거기서 멈추고 보고해 달라.

## 제약

- **프로젝트 파일을 수정하지 말 것.** 열 재배치는 QA 코드에서 `SwapField()` 를 호출해 만든다
- 산출물은 `Temp/` 아래에만. 폰트 아틀라스 4개 미접촉
- 선택 종족을 바꿨으면 끝나고 **`poker`** 로 되돌릴 것
- `PlayerPrefs` 에 QA 키를 남기지 말 것. 업그레이드 레벨을 **바꾸지 말 것** —
  현재 프로필(chess·hwatu·mahjong Lv3, slot Lv2, poker 0)이 측정 조건의 일부다
- **시간을 줄이려 이동 속도를 올리거나 트윈을 건너뛰었다면 그 사실을 보고에 적어 달라**
  (지난 QA 에서 그렇게 했고 나중에 알았다)
