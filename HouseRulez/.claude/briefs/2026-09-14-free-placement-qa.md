## 무엇을 했나

드래그가 **격자 칸 교환**이었던 것을 **자유 좌표 배치**로 바꿨다. 사용자 요청(2026-09-14).

| 파일 | 변경 |
|---|---|
| `FieldLayout.cs` | **신규** — 좌표 규칙의 유일한 소유자(간격·영역·최소거리·기본 좌표) |
| `RunUnit.cs` | `Vector2 FieldPosition` 추가 |
| `RunRoster.cs` | `SwapField` → **`SetFieldPosition`**, `IsPositionFree`, `FindFieldCell`. 자동 배치가 격자 기본 좌표 부여 |
| `UIInGameBattle.cs` | `SpawnAllies`가 칸에서 좌표를 계산하지 않고 **`runUnit.FieldPosition`을 쓴다** |
| `UIInGameField.cs` | `TryMoveUnit`, `RefreshDrawOrder`(y 정렬). 낡은 중재 3개 제거 |
| `UIInGameFieldSlot.cs` | 칸 루트가 움직인다. `IDropHandler` 제거. **빈 칸은 raycast 꺼짐** |

**9기 상한은 그대로다**(사용자 결정). 전력 천장 63이 유지되므로 밸런스 전제가 보존된다.

## 규칙

- 배치 영역 `x 0~276`, `y 0~104` — **기본 격자가 차지하던 범위 그대로**.
  넓히면 적과의 거리가 바뀌어 2026-09-14에 잡은 후반 곡선이 함께 움직인다
- 최소 간격 **54px**(열 간격 108의 절반). 겹쳐 쌓으면 `FindTarget`이 전부 같은 거리로 보고
  아군 9기가 동시에 때려 **"한 점에 모으기"가 지배 전략**이 된다
- 너무 가까우면 **거부**하고 원위치. 밀어내지 않는다(연쇄로 의도치 않은 배치가 생긴다)

## Claude 가 이미 확인한 것

- 괄호 균형 6파일, 새 API 실재, 낡은 API 제거(`SwapField`·`OnSlotDrop`·`IDropHandler` 0)
- 좌표 상수 중복 제거 — `UIInGameField`가 자체 정의를 버리고 `FieldLayout` 위임
- **`FindTarget`은 레인을 안 본다**(진영만 거르고 2D 거리) — 자유 배치가 성립하는 근거
- **`BattleUnit.lane`은 아무도 안 읽는다** — 저장만 됨
- `Promote`가 기존 개체를 재사용하므로 **승급 시 좌표가 자연 승계**된다
- 씬의 `m_AllyStartX = 0` — 저장 좌표가 전투 좌표와 그대로 일치

## 검증 항목

### 1순위 — 컴파일

6파일, 신규 클래스 1개.

### 2순위 — ★ 자유 이동이 되는가

1. 유닛을 **격자가 아닌 자리**(예: 칸 사이)에 놓을 수 있는가
2. 놓은 자리에 **그대로 머무는가**(스냅되지 않는가)
3. 다음 스핀 뒤에도 그 자리를 지키는가
4. 영역 밖으로 끌면 경계에서 잘리는가(`x 0~276`, `y 0~104`)

### 3순위 — ★ 최소 간격

1. 다른 유닛에 **54px보다 가까이** 놓으려 하면 원위치로 돌아오는가
2. 54px 바깥이면 놓이는가
3. **9기를 최대한 모았을 때** 어떤 모양인지 좌표를 적어 달라 — 밸런스 판단 재료다

### 4순위 — ★ 전투에 반영되는가 (프로덕션 경로)

배치를 **격자와 다르게** 바꾼 뒤 전투를 시작해, 생성된 `BattleUnit`의 `anchoredPosition`이
**명부의 `FieldPosition`과 일치**하는지 확인해 달라. 어긋나면 화면과 전투가 다른 자리를 쓰는 것이다.

### 5순위 — 그리기 순서

**y 가 낮은(앞) 유닛이 위에 그려지는가.** 유닛 둘을 y 만 다르게 놓고 겹쳐 보면 된다.
격자 시절에는 칸 번호가 깊이였는데 이제 좌표로 정렬한다.

### 6순위 — 빈 칸이 방해하지 않는가

유닛 수가 9 미만일 때(예: 3기), **빈 슬롯이 유닛의 드래그를 가로채지 않는가.**
빈 칸의 `raycastTarget`을 끄도록 했는데 그것이 실제로 도는지 본다.

### 7순위 — 부정 경로와 누적

| 경우 | 기대 |
|---|---|
| 전투 중 드래그 | 아무 일도 없다 |
| 빈 칸 드래그 | 시작되지 않는다 |
| **승급이 일어난 뒤** | 승급체가 **원래 자리를 지키는가**(0,0 으로 튀지 않는가) |
| 연차 이동 중 드래그 | 끌린 칸만 걷기가 멈춘다 |
| 연속 드래그 10회 | 좌표·알파·raycast 가 오염되지 않는다 |

**승급 항목이 중요하다.** `Promote`가 개체를 재사용하는 것에 기대고 있다.
