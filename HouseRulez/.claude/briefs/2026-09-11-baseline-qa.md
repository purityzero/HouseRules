## 측정 1 — 런이 어디서 끝나는가 (핵심)

런을 **최소 3회** 완주시키고 각 런마다 기록한다. 가능하면 종족을 바꿔가며.

| 기록할 것 | 비고 |
|---|---|
| 종료 연차 / 웨이브 | `RunData.year`, `waveIndex` |
| 종료 사유 | `eRunEndReason` — HomeFallen · Cleared · OutOfSpinCoin 중 무엇인가 |
| 종료 시점 본거지 HP | |
| 획득 옥새 | |

연차마다 다음을 표로 남긴다. 이게 곡선을 보는 데이터다.

- 스핀 1회당 판정 전력(`JudgeResult.Power`)과 실제 배치 전력(`placedPower`)
- 소환 유닛 수와 **등급 분포**(1성 몇 기 / 2성 몇 기 / 3성 몇 기)
- 그 웨이브 적의 수와 총 전력
- 전투 결과(승/패)와 성문을 넘은 적 수(`homeHit`)
- 연차 종료 시 골드 잔액

**중요**: 전력이 9를 넘으면 등급으로 전환되고, 63을 넘는 분은 버려진다는 규칙이 코드에 있다.
버려진 전력이 실제로 발생하는 연차가 있으면 그 값을 반드시 적어라.

## 측정 2 — 스왑이 실제로 동작하는가 (반증 요청)

정적 분석 결과 **`RunData.m_SwapCount`를 소비하는 코드가 프로젝트 전체에 0곳**이었다.
즉 HUD에 스왑 칸(핍)은 그려지지만 실제로 두 유닛을 교환하는 기능은 구현되지 않았다는 추정이다.

이 추정을 **반증하려고** 시도해 달라.

1. 전장에 유닛이 배치된 상태에서 유닛 두 칸을 교환하는 조작이 존재하는가?
   (클릭·드래그·버튼 무엇이든)
2. 스왑 핍 숫자가 줄어드는 경로가 하나라도 있는가?
3. 없다면 "미구현 확인"으로 결론내고, 있다면 **어떻게 발동하는지** 정확히 적어라.

## 측정 3 — 추가 스핀 구매

`+SPIN 25G (2)` 버튼을 실제로 눌러서 확인한다.

1. 골드가 25 이상일 때 버튼이 활성화되는가
2. 누르면 골드 -25, 스핀 코인 +1이 실제로 반영되고 **HUD와 버튼 표시가 즉시 갱신**되는가
3. 연차당 2회를 다 쓰면 버튼이 비활성화되는가
4. 골드가 부족할 때 비활성화되는가

## 검증 원칙

- **프로덕션 경로로 간다.** 콜백을 직접 호출하지 말고 실제 버튼을 클릭해라.
- **상태 플래그가 아니라 화면에 실제로 들어간 값을 읽어라.**
- 한 종족만 보고 끝내지 마라. 종족마다 판정 규칙이 달라 분포가 다르다.
