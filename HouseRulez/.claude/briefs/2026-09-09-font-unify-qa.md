## 무엇이 바뀌었나

`UIHouseUpgrade.prefab`(13곳) · `UISetting.prefab`(8곳)의 TextMeshProUGUI가
`DungGeunMo Bitmap` 폰트를 **직접 참조**하던 것을,
`LiberationSans SDF` + 폴백 체인 방식으로 교체했다(`m_fontAsset`과 `m_sharedMaterial`을 쌍으로).

YAML 직접 편집이라 **에디터로 한 번도 확인하지 않았다.**

## 검증할 것

1. 컴파일 에러/경고가 없는지
2. **업그레이드 팝업**과 **설정 팝업**의 모든 텍스트가 정상 표시되는지 —
   특히 글리프 누락(`□`)이 한 글자도 없는지
3. **한국어/영어/중국어/일본어 4개 언어를 전부 순회**해서 각 언어마다 위를 확인할 것.
   한 언어만 보고 끝내지 말 것 — 폴백 체인이 실제로 쓰이는 건 비영어권 언어다
4. 각 글자가 어느 폰트 에셋으로 실제 렌더됐는지
   (DungGeunMo / LiberationSans / PixelMplus / Vonwaon) 집계

## 지켜야 할 것

- **프로덕션 경로로 열 것.** 팝업을 코드로 직접 `Instantiate`하거나 콜백을 직접 호출하지 말고,
  타이틀 화면의 `UpgradeButton` / `SettingButton`을 EventSystem 경유로 실제 클릭해서 연다
  (`ExecuteEvents.Execute` + `pointerClickHandler`). 언어 전환도 설정 팝업의 언어 버튼을 실제로 클릭한다.
- **상태 플래그가 아니라 화면에 실제로 들어간 값을 읽을 것.**
  `TMP_Text.textInfo.characterInfo`를 순회해 실제 렌더 결과를 판정한다.
  판정 방법을 스스로 정한 뒤, **일부러 없는 글자를 넣어 그 판정이 실제로 깨지는지 1회 확인**하고
  나서 본 검증에 쓸 것. 안 깨지면 그 판정 방법은 무효다.
- 파일은 하나도 수정하지 말 것. 읽기와 Play Mode 관찰만 한다.
- 끝나면 언어 설정을 원래 값(`English`)으로 되돌리고 Play Mode를 종료할 것.

## 보고 형식

- 언어별 × 팝업별로 표시 문자 수, `□` 개수, 폰트 배정 집계
- 발견한 결함은 어느 텍스트의 어느 글자인지 유니코드 코드포인트까지 특정
- 판정 방법이 유효하다는 증거(결함 주입 확인 결과)
- 검증하지 못한 항목이 있으면 그 이유
