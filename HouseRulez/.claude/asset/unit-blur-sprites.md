# 종족 말(유닛) 스프라이트 - 블러 버전 (`_blur`)

## 왜 만들었나
슬롯머신 릴이 빠르게 돌 때 런타임 셰이더 블러 대신, 구 프로젝트 NewSlot 방식(`D:\BackUp\NewSlot\Assets\2_Script\2_Battle\SlotMachine\UIBattleSymbol.cs`의 `Blur()`)을 따라 **미리 만든 `{이름}_blur` 스프라이트로 경로만 갈아끼우는** 방식을 쓰기로 했다. 픽셀아트라 런타임 비용이 0이고 결과가 예측 가능하다. NewSlot 코드는 읽기만 했고 수정하지 않았다.

## 대상 및 결과 (2026-08-26)
`Assets/Resources/Image/InGame/Actor/` 아래 5개 폴더, 원본(`_x8` 아닌 것) 옆에 `{원본}_blur.png` + `{원본}_blur.png.meta`를 생성했다.

| **합계** | | **47** |

모든 원본이 32x32 RGBA로 동일했다.

## 사용한 도구
1순위 시도한 `pip install Pillow`가 바로 성공했다(`python -m pip install --user Pillow` → Pillow 12.3.0 설치됨). ImageMagick/ffmpeg/순수 PNG 디코딩 경로는 시도할 필요가 없었다.

## 블러 파라미터
- **방향**: 세로(수직) 방향 모션 블러만 적용(가로 번짐 없음).
- **커널**: 알파 프리멀티플라이 후 세로 1D 박스 블러(균일 가중치) → 언프리멀티플라이. 가장자리는 clamp(가장자리 픽셀 반복) 처리.
- **커널 길이**: `max(5, round(원본 높이 × 0.22))`, 짝수면 +1 해서 홀수로 보정. 32px 원본 기준 `round(32×0.22)=7` → 커널 길이 7(반경 3px). 47개 전부 동일 크기(32x32)라 전부 이 값으로 처리됨.
- **크기**: 원본 그대로 유지(리사이즈 없음).
- **알파**: 프리멀티플라이 방식으로 블러링해 투명 배경이 검게 물드는 현상 없이 보존됨.

## meta 처리
- 각 `{원본}_blur.png.meta`는 같은 폴더의 `{원본}.png.meta`를 그대로 복사한 뒤:
  - `guid`만 새 UUID(32자리 16진수)로 교체 — 교체 전 프로젝트 `Assets/` 전체 `.meta`에 grep으로 대조해 충돌 없음을 확인함.
  - 파일명이 들어간 필드(`internalIDToNameTable.second`, `spriteSheet.sprites[].name`, `nameFileIdTable`의 키)를 `{원본이름}` → `{원본이름}_blur`로 치환.
  - 그 외 필드(필터 모드, spriteMode, Pixels Per Unit, 압축 설정, `internalID`/`spriteID` 등 숫자 ID)는 원본과 동일하게 유지 — 이 ID들은 guid로 이미 파일 단위 격리되므로 그대로 둬도 무방.

## 시행착오 (기록)
생성 스크립트를 실수로 두 번 돌려서 `_blur.png`를 다시 "원본"으로 오인해 `_blur_blur.png`(및 `.meta`) 47쌍이 잠깐 생성됐었다. 발견 즉시 `find ... -iname "*_blur_blur*" -delete`로 전량 삭제했고, 최종 파일 목록(폴더별 개수, `_blur_blur` 잔존 없음)을 재확인했다. 원본(`_x8` 포함) 파일은 이 과정에서 전혀 건드리지 않았다(픽셀 값이 결정론적이라 최종 `_blur.png`는 정상 결과물).

## 미검증 사항
**Unity 에디터에서 실제로 임포트해 확인하지 못했다.** 이 세션은 파일 시스템 레벨 작업만 수행했고, 에디터를 열어 스프라이트 임포트 결과(썸네일 정상 생성 여부, GUID 충돌로 인한 에셋 유실 여부, `spriteMode`/필터 모드가 의도대로 반영됐는지)를 육안 확인하지 않았다. 다음 세션에서 에디터로 열어 임포트 로그와 스프라이트 썸네일을 확인할 것.
