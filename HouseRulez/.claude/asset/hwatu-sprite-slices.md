# 화투 스프라이트 슬라이스 — 심볼 풀이 12가 아니라 15였던 문제

연관: `HouseSpriteLoader`(`Assets/Scripts/Table/HouseRecord.cs:43`), [[Judge]], [[UIHouseSlotMachine]]

## 2026-08-30-0 — 자동 슬라이스가 그림을 조각내 유령 심볼 3개를 만들었다

### 증상
화투로 스핀하면 grid에 **12가 등장했다.** 심볼 풀이 12종이면 인덱스는 0~11이어야 한다.
(Codex QA가 지나가듯 남긴 관찰에서 시작됐다 — 그 스핀 자체는 콘솔 에러 없이 정상 판정됐다)

### 원인
`hwatu_07_redclover.png`와 `hwatu_08_moon.png`가 `spriteMode: 2`(Multiple)인데,
**그림에 서로 떨어진 덩어리가 있어** Unity 자동 슬라이스가 덩어리마다 스프라이트를 만들었다.

| 파일 | 슬라이스 | 내용 |
|---|---|---|
| `hwatu_07_redclover` | 3개 | 좌 송이 11×23 · 전체 26×30 · 우 송이 11×23 |
| `hwatu_08_moon` | 2개 | 산 26×15 · **달 15×15** (위아래로 완전히 분리) |
| (블러 짝 2개도 동일) | | |

`HouseSpriteLoader.Load`는 `Resources.LoadAll<Sprite>` 결과에서 `_blur`/`_x8`만 걸러낸다.
조각은 그 필터에 안 걸리므로 **풀이 12가 아니라 15**가 됐다.

### 왜 조용했나
1. `HouseTable.csv`의 `PoolCount`는 **어떤 코드도 읽지 않는다.** 실제 풀은 스프라이트 개수다 —
   문서용 숫자와 실제 동작이 갈라져도 아무도 모른다(전형적인 이중 소스)
2. 판정기가 붙기 전에는 풀 크기가 릴 그림에만 영향을 줘서, 이상한 조각이 가끔 보여도
   "아트가 좀 이상한가" 정도로 넘어갔다

### 영향
화투 판정은 **심볼 인덱스 + 1 = 월**이다(`Judge.EvaluateHwatu`).
풀이 15면 존재하지 않는 **13·14·15월**이 생겨 광/특수 판정과 끗 계산이 어긋난다.

### 수정 — 조각을 지우지 않고 하나로 합쳤다
조각을 지우기만 하면 **8월의 달이 사라진다**(달과 산이 별개 조각이라).
그래서 실제 불투명 경계상자를 덮는 조각 하나로 교체했다.

여백 1px은 형제 파일의 기존 관례를 따랐다 — `hwatu_01_pine`은 실제 경계 `(4,0,24,29)`에
meta rect `(3,0,26,30)`으로, 사방 1px(캔버스 밖은 클램프)이 붙어 있다.

| 파일 | 수정 후 rect | 슬라이스 |
|---|---|---|
| `hwatu_07_redclover` | (3, 0, 27, 32) | 3 → 1 |
| `hwatu_07_redclover_blur` | (3, 0, 27, 32) | 3 → 1 |
| `hwatu_08_moon` | (3, 0, 26, 30) | 2 → 1 |
| `hwatu_08_moon_blur` | (3, 0, 26, 32) | 2 → 1 |

★ 남긴 조각의 이름을 `{파일명}_0`으로 맞췄다. 블러 짝짓기가 **이름 기반**이라
(`{블러이름}에서 _blur를 뺀 것 == 원본 이름`) redclover에서 살린 게 `_1`이면 짝이 끊긴다.
★ `spriteID`/`internalID`는 그대로 뒀다 — 바꾸면 이 스프라이트를 참조하던 곳이 끊긴다.

### 검증 (Codex, Play Mode)
- 7종족 런타임 풀: slot 6 / chess 6 / janggi 7 / **hwatu 12** / poker 13 / mahjong 9 / yut 6 — 전부 `PoolCount`와 일치
- `CreateRandomGrid()` 500회 4,500칸: 최소 0 / **최대 11** / 12 이상 0회
- 두 심볼 rect가 불투명 영역 전체를 덮음. 화면에서 7월 좌우 송이와 8월 달·산이 온전히 표시됨
- 블러 사전 12개, 12개 전부 짝 성립
- 화투 판정 20만 회: 평균 6.219 / CV 1.524 (목표 6.20 / 1.53), 13~15월 흔적 없음

### 같은 함정을 다시 안 밟으려면
- **그림에 떨어진 덩어리가 있는 픽셀아트를 추가할 때는 슬라이스 개수를 확인한다.**
  파일 1개 = 스프라이트 1개라고 가정하지 말 것
- 점검 방법: `.meta`에서 `^      name: ` 줄 수를 센다. 1이 아니면 조각난 것이다
- `PoolCount`처럼 **아무도 안 읽는 숫자**는 실제와 갈라져도 조용하다. 실제 소유자는 스프라이트 개수다
