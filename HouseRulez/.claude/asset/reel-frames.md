  - 좌우 기둥: x 4–20, x 116–132, y 21–170 — 종족별 재질 텍스처(석재 켜쌓기, 목재 결, 격자 등).

### meta 처리 (Unity 임포트 설정)
지시받은 `chess_king.png.meta`를 열어 대조한 결과, 실제 값이 **Bilinear 필터(`filterMode:1`) + 압축(`textureCompression:1`)** 이었다 — "Point 필터 / 무압축"이라는 지시 문구와 어긋났다. 같은 폴더의 `Assets/Resources/Image/Title/ui_white.png.meta`(spriteMode 1 단일 스프라이트, Point 필터)와 `bg_chess_castle.png.meta`(전 플랫폼 무압축)를 함께 대조해, **"Point 필터/무압축"이라는 지시 문구의 실제 의도에 맞는 쪽**을 최종 템플릿으로 썼다:
- `filterMode: 0`(Point), 4개 플랫폼 블록(`DefaultTexturePlatform/Standalone/Android/iOS`) 전부 `textureCompression: 0`(무압축) — 이 조합은 `bg_chess_castle.png.meta`와 동일.
- `textureType: 8`(Sprite), `spriteMode: 1`(Single, 트리밍 없이 136×260 풀캔버스 그대로 사용), `alphaIsTransparency: 1`, `spritePixelsToUnits: 100` — 이 조합은 UI용 단일 스프라이트인 `ui_white.png.meta`와 동일.
- `guid`는 프로젝트 전체 `.meta`(약 1.6만 개) grep 대조 후 겹치지 않는 새 UUID 6개(폴더 1 + PNG 5) 발급.
- 파일명이 들어가는 필드(`internalIDToNameTable.second`, `spriteSheet.sprites[].name`, `nameFileIdTable` 키)는 각각 `frame_{종족}_0`으로 채움. `spriteID`/`internalID`는 파일마다 새로 랜덤 생성(전역 유일성이 필수는 아니지만 파일별로 구분되게 함).

**이 결정은 지시 문구("Point/무압축")를 우선하고, 지시에서 예시로 든 파일(chess_king)의 실제 값과는 의도적으로 다르게 갔다는 뜻이다.** 릴 프레임이 배경/UI 패널 성격(작은 액터 스프라이트처럼 확대·회전되며 안티에일리어싱이 필요한 대상이 아님)이라 Point+무압축이 실제로도 더 맞는 선택으로 판단했다.

### 육안 확인
5장 모두 Read 도구로 원본 크기 + 4배 확대(NEAREST) 두 배율로 열어 확인:
- 릴 창이 규격대로 96×96, 가로 중앙(20–116, 캔버스 중심 68과 일치)에 정확히 위치.
- 헤더 액센트가 5색 모두 뚜렷이 구분됨.
- 도트가 뭉개지지 않고 1px 단위로 또렷함(그라데이션 없음).
- `#363B4A`보다 어두운 픽셀 없음(스크립트 검증 + 최종 배치 파일 재검증 모두 0건).
- 릴 창 내부는 5장 모두 장식 없이 `#393E4E` 단색 평면.
