### `Power`가 밸런스의 기준 단위다
**플레이어 1성 유닛 1기 = 1.** 이 적 한 마리가 그 몇 기에 해당하는지를 뜻한다.
웨이브가 몇 마리를 낼지는 이 값으로 역산하므로([[WaveRecord]]), `Hp`/`Atk`을 고칠 때 `Power`도 함께 본다.
★ `Power`만 고치고 스탯을 안 고치면 마릿수만 변하고 실제 체감 난이도는 그대로다 — 반대도 마찬가지.

## 2026-09-14 — `king_final` 조정 (기획 관문 통과)

### 왜

기획서 12장 관문 **"단일 종족(체스)만으로 12연차 클리어율 20~35%"**가 누적 0/22로 실패하고 있었다.
원인이 최종 보스의 산술에 있었다.

| | 값 | 문제 |
|---|---:|---|
| `king_final.Atk` | 78 | **아군 3성 Hp 70보다 크다 → 한 방에 죽는다** |
| `king_final.Hp` | 1650 | 아군이 9초 안에 전멸하며 넣는 누적 피해는 630 |

`14 × (9+8+…+1) = 630` 대 `1650`. **만렙(3성 9기)으로도 62% 부족**했다.

### 수정

| 항목 | 전 | 후 | 근거 |
|---|---:|---:|---|
| `Atk` | 78 | **55** | 3성이 **2방**을 버틴다 → 생존 시간·누적 피해가 그대로 2배 |
| `Hp` | 1650 | **850** | 실측 4회로 850에서 클리어율 25%를 맞췄다 |
| `Power` | 110 | **110 (불변)** | 아래 참조 |

### ★ `Power`를 건드리면 보스가 여러 기 나온다

`Power`는 `WaveRecord.GetSpawnCount`의 마릿수 역산에만 쓰인다.

```csharp
int count = Mathf.RoundToInt(GetTargetPower(_record, _basePower) / _enemy.Power);
return Mathf.Max(1, count);
```

12-3의 목표 전력이 110.4이므로 `RoundToInt(110.4 / 110) = 1`이다.
`Power`를 낮추면 **2 이상이 되어 보스가 복수로 등장한다.** Hp/Atk만 바꾼다.

그 결과 **전력 지표와 실제 강함이 어긋난다** — 이 불일치는 2026-09-13에 이미 기록됐다
(3성 1기와 잡병 7마리는 전력이 같아도 동시 교전 수 제한 때문에 집중된 쪽이 이긴다).

### 같은 이유로 `PowerCoef`는 12-3에 효과가 없다

12-1·12-2는 `brute` 다수라 계수가 마릿수를 바꾸지만, **12-3은 보스 1기라 계수를 아무리 낮춰도
`Max(1, …)`로 1마리가 나온다.** 후반 완화를 계수로만 시도하면 마지막 웨이브는 그대로 남는다.

### 측정 경과

| 보스 HP | 체스 클리어율 |
|---:|---|
| 1650(원래) | 0/22 (누적) |
| 1100 | 0/6 |
| 950 | 1/8 |
| 900 | 1/8 |
| **850** | **2/8 = 25%** ← 채택 |

**950과 900이 같게 나온 것**이 분해의 계기였다 — 보스 **도달 실패**가 3/8이라 보스 HP를 낮춰도
그 런들은 영향을 받지 않는다. 최종 분해는 도달 6/8 · 도달 후 승리 2/6 · 전체 2/8이다.

실패 4런의 보스 잔여 HP가 **54.8 / 52.0 / 44.3 / 55.5**로 모두 60 이하,
클리어 런도 아군 1~2기 생존. 거의 모든 보스전이 마지막 순간에 갈린다.
