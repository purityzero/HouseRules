# HandbookText

연관: [[UIInGameSummary]], `JudgeTable`, [[UnitRecord]], `StringTable`, [[RunRoster]]

## 2026-09-14 — 신설 (족보·유닛 설명 생성)

### 개요
종족의 **족보**와 **유닛 특성**을 사람이 읽는 글로 만든다.
사용자 요청: "각 종족별 당첨규칙(족보), 그 유닛의 특성을 알 수 있는 방법이 있어야겠어"

파일: `Assets/Scripts/InGame/UI/HandbookText.cs`

### 왜 화면 클래스와 분리했나
보여주는 자리는 바뀔 수 있다 — 지금은 접이식 패널이지만 도감 화면이나 툴팁이 될 수도 있다.
글을 만드는 규칙이 화면 안에 있으면 자리를 옮길 때 따라다니거나 **두 화면이 각자 다시 구현한다.**

### 공개 API
| 메서드 | 하는 일 |
|---|---|
| `BuildPattern(houseKey)` | 그 종족의 족보. 배수 큰 것부터 |
| `BuildUnit(houseKey, roster)` | **지금 전장에 선** 유닛의 이름·역할·실제 스탯·특성 |

### 테이블이 정본이다
계수는 `JudgeTable`, 스탯은 `UnitTable`, 문구는 `StringTable` 에서 온다.
숫자도 문장도 여기 박아 넣지 않는다.

### 슬롯은 접어서 보여준다
`SlotMatch3_0` ~ `_5`, `SlotMatch2_0` ~ `_5` 는 **12개 키지만 규칙은 2가지**다
(심볼마다 계수가 다를 뿐). 그대로 늘어놓으면 12줄이 되어 안 읽힌다.
대표 키로 접고 배수는 범위로 적는다 — `×3~33  페이라인 세 칸이 같은 심볼`.

### 종족 전체가 아니라 전장에 선 것만
포커는 심볼이 13개다. 전부 늘어놓으면 화면을 넘기고,
정작 궁금한 것은 **내가 지금 가진 말**이다.

### 배율이 아니라 실제 값을 보여준다
`UnitTable` 의 `HpRate` 는 0.74 같은 배율이라 그 자체로는 세다 약하다를 말해주지 않는다.
`GetBattleStat` 으로 성급을 곱한 뒤의 값을 적는다.

### 실측 (2026-09-14)
7종족 모두 족보 글이 생성됐다(빈 종족 0, 키 노출 0).

```
poker    ×40  한 줄 세 칸이 모두 같은 숫자
         ×11  한 줄 세 칸이 연속된 숫자
         ×1   한 줄에 같은 숫자 두 칸
mahjong  ×56  1~9를 세 면자로 이어 붙인 일기통관
         ×24  아홉 칸이 세 면자로 남김없이 나뉜 화료
         ...
```

### ⚠️ 확인 못 한 것
고유 유닛 이름(`UnitPokerTripleUnit` 등) 2행을 나중에 `StringTable` 에 넣었는데,
**에디터의 `TableManager` 가 옛 캐시를 들고 있어 화면 확인을 못 했다.**
`TableManager.init()` 에 `m_isInitialized` 가드가 있어 CSV 를 고쳐도 다시 읽지 않는다.
CSV 와 `verify-tables` 는 통과했고 에셋도 최신(180줄)이므로 **Play Mode 를 새로 시작하면 정상일 것**으로 보이나,
그 시점에 Codex 가 같은 에디터에서 측정 중이라 Play Mode 를 껐다 켤 수 없었다.
