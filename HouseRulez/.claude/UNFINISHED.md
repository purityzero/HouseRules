## 브랜치 4 — `work/2026-08-27-ingame-hud` (오늘, 전부 미검증)

`work/2026-08-27-title-to-ingame` 위에 쌓았다.

인게임 상단 HUD(본거지 HP·연차·골드·스핀 코인·판돈)와 하단 ACTION 바(전투 시작·스왑·배속)를 배치하고,
표시할 값을 담을 런 상태(`RunData`)와 초기값 테이블(`GameConfigTable`, `SutdaBetTable`)을 새로 만들었다.

**이 브랜치는 브랜치 1~3과 성격이 다르다 — 실행 검증을 하나도 못 했다.**
세션이 열린 뒤에 에디터를 켜서 **MCP가 이 세션에 붙지 않았다**(아래 재발 방지 메모 그대로 다시 밟았다).
그래서 씬 YAML을 직접 작성했고 컴파일조차 돌리지 못했다.

**기계 검증으로 통과한 것 (파일 정합성일 뿐, 화면과는 무관)**
- 씬 fileID 중복 0건(전체 138 블록, 신규 74) / dangling 참조 0건 / 신규 블록 고아 0건
- GameObject `m_Component` ↔ 컴포넌트 `m_GameObject`, RectTransform `m_Children` ↔ `m_Father` 상호 일치
- 개행 LF 유지, 신규 GUID 7개 프로젝트 전체 중복 없음
- CSV 헤더 ↔ Record 필드명 눈 대조

**남은 검증 — 에디터를 먼저 띄우고 새 세션에서**
1. **컴파일 에러 0건** — 서브에이전트 없이 한 세션에서 쓴 코드지만 컴파일을 못 돌렸다
2. 씬이 열리는가 / HUD 띠와 ACTION 바가 화면에 뜨는가
3. 핍이 테이블 값대로 생기는가 — HP 8칸, 스핀 코인 3개, 스왑 2칸
4. 라벨이 한글로 뜨는가(StringTable 키 8개 신규) — 폰트 글리프 문제 가능성
5. **SPIN 3번 누르면 코인 핍이 3→2→1→0으로 줄고 4번째엔 아무 일도 안 일어나는가** (이번에 처음 물린 규칙)
6. 배속 버튼을 누르면 라벨이 ×1 ↔ ×2로 바뀌는가
7. **화투를 고르면 우측에 "판돈 0 ×1.0"이 뜨고, 다른 4종족에선 그 자리가 비는가** (`isUseBet` 컬럼)
8. `HouseTable.csv`에 컬럼을 하나 늘렸다 — **다섯 행 전부 값이 있어야 하고, 하나라도 비면 테이블 로드가 통째로 실패**한다. 종족 선택 화면까지 함께 확인할 것

**아직 안 되는 게 정상인 것** (스텁으로 둔 것 — 버그로 오해하지 말 것)
- 전투 시작 버튼: 로그만 찍는다(전투 단계 없음)
- 스왑 잔여: 항상 최대치(스왑을 쓰는 배치 단계 없음)
- 배속: 표시만 바뀐다(적용할 전투 없음)
- 연차/HP/골드: 초기값에서 안 변한다(연차 진행·전투·상점 없음)

**관련 파일**: `Assets/Scripts/InGame/RunData.cs`, `Assets/Scripts/InGame/UI/` 2개,
`Assets/Scripts/Table/GameConfigRecord.cs`·`SutdaBetRecord.cs`, `Assets/Resources/Table/` CSV 4개(신규 2 + 수정 2),

## 재발 방지 메모 (계속 유효)

**MCP는 세션 시작 시점에 한 번만 붙는다.** 세션이 열린 뒤 에디터를 켜면 그 세션에는 안 붙고,
`--continue`로도 복구되지 않는다(세션 상태를 그대로 복원). **에디터를 먼저 띄운 뒤 새 세션을 열 것.**

**콘솔 로그 조회(`read_console`)가 로그를 못 가져오는 경우가 있다.** 2026-08-27에
`Debug.Log`를 직접 호출해도 0건으로 나왔다. 로그가 안 보인다고 "그 코드가 안 불렸다"고
판단하면 엉뚱한 곳을 파게 된다 — 호출 여부를 봐야 하면 **관측 가능한 상태(카운터 등)로 확인할 것.**
