### 증상


### 지금 당장의 피해는 없다

받아야 하는 연출이 생기면 그때 조용히 어긋난다.

### 고치려면
로드→언로드 순서 자체는 옳다(반대로 하면 빈 화면 프레임이 생긴다). 그래서 **EventSystem을 하나만 두는 쪽**이 맞다.

  `SceneManager.cs:54`에 이미 "싱글톤 매니저는 씬을 넘어 유지" 개념이 있다
- (b) 새 씬 로드 직후 중복 EventSystem을 비활성화 — 국소적이지만 미봉책
- (c) 그대로 둔다

### 3. 윷 판정기 (⬜ 미검증)
`Judge.EvaluateYut`. **다른 여섯 종족과 구조가 다르다** — 전력으로 칸을 채우는 게 아니라
줄마다 칸·심볼·등급이 먼저 정해지고 전력이 그 결과다. 그래서 `BuildSummon`을 타지 않는다
(`Evaluate`가 `ListSummon.Count <= 0`일 때만 `BuildSummon`을 부르도록 바꿨다).

**`SummonSlot`에 `SymbolType` 추가** — 지금까지 표시 쪽이 `grid[Cell]`로 심볼을 복원했는데,
윷은 말의 종류와 서는 칸이 무관해서(도착점 트랙) 복원이 안 된다.
기본값 `-1`(`SYMBOL_FROM_GRID`)이라 나머지 6종족 경로는 그대로다.
소비처 2곳 수정: `UIInGameField.ShowSummon`, `UIInGameBattle.SpawnAllies`.

**트랙 매핑**: `t = (Landing-1) % 9`, `cell = (t%3)*3 + (t/3)` → 후열(0,3,6) → 중열(1,4,7) → 전열(2,5,8)
**등급**: 1 + (도착점 ≥ `YutGrade2Landing`) + (완주 = 도착점 > 9) + (업기 겹침마다 1), 상한 3성

**튜닝 (전수 계산 5832 조합)**: `YutGrade2Landing = 11` → 평균 **6.120** / SD 3.458 / **CV 0.565** /
무소환 0.001% / 평균 2.63기. 목표 6.1~6.3 안이고 CV는 전 종족 최저 —
기획서의 "낮은 실패율로 꾸준히 전진"과 맞고 분산 사다리를 아래로 넓힌다.

★ **`YutGrade3Landing`은 만들었다가 뺐다.** 완주(+1)가 도착점 10 이상을 이미 덮어
어떤 값을 넣어도 발동하지 않는 죽은 손잡이였다. 3성은 완주가 담당하고, 윷의 레버는 숫자 하나다.

★ 구현 중 잡은 버그: 업기를 "도착점이 같으면"으로 짜면 안 된다. 트랙이 9칸에서 감기니

## 재발 방지 메모 (계속 유효)

**MCP는 세션 시작 시점에 한 번만 붙는다.** 세션이 열린 뒤 에디터를 켜면 그 세션에는 안 붙고,
`--continue`로도 복구되지 않는다(세션 상태를 그대로 복원). **에디터를 먼저 띄운 뒤 새 세션을 열 것.**

**콘솔 로그 조회(`read_console`)가 로그를 못 가져오는 경우가 있다.** 2026-08-27에
`Debug.Log`를 직접 호출해도 0건으로 나왔다. 로그가 안 보인다고 "그 코드가 안 불렸다"고
판단하면 엉뚱한 곳을 파게 된다 — 호출 여부를 봐야 하면 **관측 가능한 상태(카운터 등)로 확인할 것.**
