## 무엇이 바뀌었나

### A. 배너 스포일러 — 2차 수정
1차 수정(고정 0.9초 대기 뒤로 배너 이동)이 **불충분**하다고 직전 QA가 판정했다.
릴 감속이 프레임당 이동량 기반이라 정지 소요가 프레임레이트를 탄다(52fps 1.00초 / 23fps 1.69초).
→ 고정 대기를 **실제 정지 완료 대기**로 교체했다:
`yield return new WaitUntil(() => m_SlotMachine.isAllReelIdle);`
`UIHouseSlotMachine`에 `public bool isAllReelIdle` 접근자를 새로 노출했고, `m_SummonDelay` 필드는 제거했다.

### B. 전투 결과 처리 신설
전투 결과를 **아무도 읽지 않던** 상태였다(`m_Battle.result` 소비처 0곳). 그래서 전투가 끝나도
결과가 안 나오고, 웨이브도 안 넘어가고, 스핀이 무제한으로 눌렸다. 붙인 것:
- `m_isBattleActive` 플래그 신설 + `Update()`에서 전투 종료 프레임을 1회만 잡아 `OnBattleFinished()`
- 승리 → `RunData.AdvanceWave()` / 패배 → `RunData.TakeHomeDamage(homeHit)` → HUD 갱신 → 배너로 결과 표시
- `OnClickSpinButton()`에 가드 추가 — **코인 차감보다 앞에** 놓았다(스핀 중/전투 중이면 무시)
- 전투 시작에도 가드 추가(전투 중/릴 회전 중이면 무시)
- `StringTable.csv`에 `InGameBattleVictory`(승리!) · `InGameBattleDefeat`(패배…) 2행 추가

## 검증 항목 5개 — 요구마다 1:1로 단언할 것

1. **씬 진입 즉시 유령 승리가 나지 않는가 (부정 경로, 최우선)**
   `UIInGameBattle.m_Result` 초기값이 `Running`이고 `Tick()`에 유닛 수 가드가 없어서,
   `m_isBattleActive` 플래그가 없으면 **전투 시작 전에 "적이 0기 = 승리"로 판정**된다.
   인게임 진입 후 아무것도 누르지 않은 상태에서 **웨이브 번호가 저절로 오르지 않는지,
   배너가 뜨지 않는지** 확인하라. 이번 수정에서 가장 위험한 지점이다.
2. **전투가 끝나면 결과 배너가 뜨고 웨이브가 실제로 넘어가는가**
   SPIN → BATTLE로 전투를 한 번 끝내고 ①배너에 `승리!` 또는 `패배…`가 뜨는지
   ②`RunData.waveIndex`(HUD 표시값)가 승리 시 실제로 +1 되는지 — **상태 플래그가 아니라 화면에 들어간 값**
   ③키 문자열(`InGameBattleVictory`)이 그대로 뜨지 않는지(그러면 CSV 로드 실패다)
3. **스핀 연타에 코인이 새지 않는가 (부정 경로)**
   릴이 도는 중 SPIN을 5회 이상 연타하고 **스핀 코인이 정확히 1만 줄었는지 계수로 단언**하라.
   전투 중 SPIN 연타는 코인이 0 줄어야 한다. 전투 중 BATTLE 연타 시 전투가 재시작되지 않는지도.
4. **배너가 릴 3개 전부 멈춘 뒤에 뜨는가 (A의 재검증)**
   `CanvasGroup.alpha`가 0을 벗어나는 시점 vs 릴 3개 전부 Idle이 되는 시점을 동시 샘플링해 비교하라.
   직전 측정에서 고정 0.9초일 때 52fps에서 0.09초, 23fps에서 0.64초 **이르게** 떴다. 이제 0 이상이어야 한다.
5. **콘솔 에러 0건**
   (기존 `TableManager.cs(80,32) CS1998` 경고와 EventSystem 2개 경고는 알려진 것이라 제외)
