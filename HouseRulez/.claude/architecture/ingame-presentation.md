# 인게임 연출 — 드래그 배치 · 제자리 복귀 · 연차 이동

**상태**: 1번(드래그 배치) **부분 구현 — 전장 칸끼리 교환만**. 2·3번 미구현. (2026-09-13 갱신)
**관련**: [[RunRoster]] · [[UIInGameField]] · [[UIInGameFieldSlot]] · [[UIInGameBattle]] · [[BattleUnit]] · [[InGameScene]] · [[TitleBackgroundScroller]]

사용자 요청 3건(2026-09-12). 셋이 **하나의 흐름으로 엮인다** — 배치하고, 싸우고, 제자리로 돌아오고, 다음 연차로 걸어간다.

---

## 1. 유닛 위치를 플레이어가 옮긴다 (드래그 배치)

### 이미 있는 것

[[RunRoster]]에 **이동 API가 이미 다 있다.** 코드를 새로 설계할 게 없다.

| 메서드 | 하는 일 |
|---|---|
| `MoveBenchToField(benchIndex, cell)` | 보관함 → 전장. 점유된 칸이면 **자리를 맞바꾼다** |
| `MoveFieldToBench(cell)` | 전장 → 보관함 |
| `SwapField(from, to)` | 전장끼리 교환. 한쪽이 비어 있어도 성립 |

이동 후 `MergeAll()`도 안에서 부르므로, 옮기다가 3기가 모이면 그 자리에서 승급한다.

### 없는 것

- `UIInGameFieldSlot`이 **표시 전용**이다(`Clear`/`SetUnit`만). 드래그 인터페이스가 없다
- **보관함 UI 자체가 없다.** 지금은 `FillFieldFromBench()`가 앞 칸부터 자동으로 채우는 게 전부다

### 필요한 작업

| 무엇 | 담당 |
|---|---|
| `UIInGameFieldSlot`에 `IBeginDragHandler`·`IDragHandler`·`IEndDragHandler`·`IDropHandler` 구현 | **코드 — Claude Code** |
| 보관함 `UIInGameBench` + `UIInGameBenchSlot` 클래스 | **코드 — Claude Code** |
| 씬에 보관함 오브젝트 배치, 슬롯 프리팹, 드래그 고스트 이미지 | **씬·프리팹 — Codex** |

**드래그 중 미리보기(고스트)가 필요하다.** 원본을 그대로 끌면 놓는 순간까지 원래 칸이 빈 것처럼 보인다.

### 구현 결과 (2026-09-13) — 씬 작업 없이 전장 교환까지

| 예정 | 실제 |
|---|---|
| `UIInGameFieldSlot`에 드래그 인터페이스 | **구현.** 4개 모두(`IBeginDrag`/`IDrag`/`IEndDrag`/`IDrop`) |
| 보관함 `UIInGameBench` + `UIInGameBenchSlot` | **안 만들었다.** 아래 참조 |
| 씬에 보관함 오브젝트, 슬롯 프리팹, 고스트 이미지 | **불필요해졌다.** 씬 작업 0 |

**씬 작업이 필요 없어진 이유** — 씬의 `SlotTemplate`에 `Image`가 없어 포인터를 못 받는데,
칸은 템플릿을 `Instantiate` 한 런타임 오브젝트이므로 `AddComponent<Image>()`(alpha 0)로
코드가 붙인다. 고스트도 별도 오브젝트 없이 **원본 심볼을 직접 옮기고 끝날 때 되돌린다.**

**보관함 UI를 이번에 안 만든 이유** — 전장 9칸 교환만으로 사용자 요청("유닛 위치도 내가 옮길 수
있게")이 충족되고, 밸런스 병목(배치가 전투력을 좌우한다)도 그 범위에서 풀린다.
보관함은 새 오브젝트·프리팹이 필요해 씬 작업(Codex)과 묶여야 하므로 분리했다.
**그래서 `RunRoster.MoveBenchToField()`·`MoveFieldToBench()`는 아직 호출부가 없다.**

### 선행 조건이 함께 처리됐다

`ArrangeFieldByGrade()`가 매 스핀 9칸을 다시 세워 **플레이어 배치를 덮어쓰는** 문제가 있었다.
그 함수 주석에 제거 조건("드래그 핸들러가 붙는 시점")이 적혀 있었고, 이번에
`FillEmptyFieldFromBench()`(빈 칸만 채움)로 좁혔다. 이것 없이는 드래그가 무의미했다.

### 스왑 잔재 정리 완료 (2026-09-13, 드래그 검증 후)

드래그가 Play Mode 검증을 통과한 뒤 별 브랜치(`work/2026-09-13-swap-to-extraspin`)에서 걷어냈다.
같이 건드리지 않은 이유는 "무엇이 깨졌는지 가릴 수 없어서"였고, 그 순서대로 했다.

**설계안이 놓친 것이 있었다** — 이 절은 `RunData.m_SwapCount`·`GameConfigTable` 키·`UIInGameAction`
핍만 셌지만, **스왑은 업그레이드 트리의 한 축이기도 했다**(`HouseUpgradeTable`에 7종족 × 최대 3레벨,
총 17행, 가격 옥새 3/6/12). 사용자 세이브에 실제 구매 기록이 있어 그냥 지우면 옥새 72개가 사라진다.

그래서 **노드 키 `swap`을 유지한 채 `TargetKey`만 `ExtraSpinMaxPerYear`로 바꿨다.**
세이브와 옥새가 그대로 유효하고, 산 레벨이 그대로 새 효과가 된다.
마침 실측에서 그 상한이 새 병목이었다 — 죽은 노드가 살아났다.

### ⚠️ 선행 — 스왑 잔재

`RunData.m_SwapCount`·`GameConfigTable.KEY_SWAP_COUNT_PER_YEAR`·`UIInGameAction`의 스왑 핍이
아직 남아 있다. 드래그가 그 역할을 대신하므로 **이 작업에서 함께 걷어낸다.**
(미완료 항목의 `SwapText` 폭 여유 0 결함도 이때 같이 사라진다)

## 2. 전투가 끝나면 유닛이 제자리로 돌아간다

### 지금 무슨 일이 일어나는가

**전투가 끝나도 유닛이 화면에 그대로 남는다.** `UIInGameBattle.Clear()`는 다음 전투의 `Begin()`
첫 줄에서만 불리기 때문이다. 그래서 전투 직후 화면은 이렇게 된다.

- 죽은 유닛은 사라지고, 살아남은 유닛은 **적진 앞에 몰린 위치 그대로** 방치된다
- `m_Field`는 `OnBattleStart`에서 `Clear()`돼 비어 있다 — 전장 9칸 표시가 없다
- 다음 스핀을 돌리면 그제서야 `m_Field.Show()`가 전장을 다시 그린다

즉 **전투와 배치 사이에 화면이 "아무 상태도 아닌" 구간**이 있다. 사용자가 지적한 지점이다.

### 설계

`OnBattleFinished()`에서 **살아남은 유닛을 원래 칸으로 걸어서 돌려보낸다.**

```
전투 종료 판정
  → 결과 배너
  → 살아있는 유닛을 각자의 전장 칸 좌표로 이동 (걷는 연출)
  → 도착하면 m_Battle.Clear() + m_Field.Show(roster, ...)
  → 다음 스핀 대기
```

**왜 Clear를 먼저 하지 않는가** — 지우고 다시 그리면 순간이동으로 보인다. 걸어서 돌아가는 것이
"내 유닛이 살아 돌아왔다"를 보여주는 장면이므로, 이동이 끝난 **뒤에** 전투 오브젝트를 정리한다.

### 재사용

- **이동은 `BattleUnit`에 이미 있다** — `m_MoveSpeed = _moveSpeed * CELL_TO_PIXEL`로 목표를 향해 움직인다.
  복귀도 "목표 좌표를 원래 칸으로 바꾸는 것"이라 같은 로직을 쓴다
- **원래 칸 좌표는 `UIInGameBattle.GetLanePosition(lane, m_AllyStartX + column * 108f)`**가 이미 계산한다.
  `SpawnAllies`가 세울 때 쓴 그 값을 유닛이 들고 있으면 된다
- **흐름 제어는 `FlowCommand`** — `Command_WaitUntil(모두 도착했는가)` 다음에 `Command_Delegate(정리)`.
  코루틴을 새로 쓰지 않는다(프로젝트 관례)

### ⬜ 정할 것

1. **죽은 유닛은 어떻게 보이나** — 로스터에는 살아 있으므로 다음 웨이브에 다시 선다.
   복귀 연출에서 빈 칸으로 둘지, 회색으로 되살아나 걸어올지
2. **패배했을 때도 복귀 연출을 하나** — 아군이 전멸하면 돌아올 유닛이 없다.
   그 경우 바로 정리로 넘어가야 한다
3. **배속(`battleSpeed`)이 복귀 이동에도 적용되나** — 적용하는 쪽이 자연스럽다

## 3. 연차가 바뀔 때 배경이 움직이고 걸어간다

### ★ 재사용할 것이 이미 있다

**`TitleBackgroundScroller`**(`Assets/Scripts/Title/TitleBackgroundScroller.cs:6`)가
`RawImage.uvRect`를 한쪽으로 밀어 **끊김 없는 가로 스크롤**을 만든다. 배경 텍스처가 가로 seamless라 가능하다.

그리고 **인게임 배경도 같은 `RawImage`다**(`InGameScene`의 `m_BackgroundImage`).
즉 **그대로 붙는다.** 새로 만들 게 없다.

다만 타이틀은 **항상** 스크롤하고 인게임은 **연차 전환 때만** 움직여야 하므로,
"일정 시간 동안만 스크롤" 하는 제어가 필요하다. 클래스를 고치기보다
`FlowCommand`로 켜고 끄는 쪽이 최소 침습이다.

### 설계

연차 전환은 지금 `AdvanceToNextWave()` → `m_RunData.AdvanceWave()`가 true면
`ShowYearStartBanner(year)`로 배너만 띄운다. 여기에 이동 연출을 끼운다.

```
웨이브 승리
  → AdvanceWave()가 true (연차가 넘어갔다)
  → 유닛들이 화면 오른쪽을 향해 걷기 시작
  → 배경 스크롤 on
  → (이동 구간, 수 초)
  → 배경 스크롤 off, 유닛 정지
  → 연차 시작 배너
  → 다음 웨이브 준비
```

배경이 오른쪽으로 흐르고 유닛은 제자리걸음을 하면 **"우리가 이동했다"**로 읽힌다.
실제로 유닛을 화면 밖까지 옮길 필요가 없다.

### 필요한 것

| 무엇 | 담당 |
|---|---|
| 연차 전환 흐름을 `FlowCommand`로 구성, 스크롤 on/off | **코드 — Claude Code** |
| `BattleUnit`에 "제자리걸음"(이동 없이 걷는 표시) | **코드** — 걷는 표현이 스프라이트 애니메이션이면 프리팹도 필요 |
| 인게임 배경에 `TitleBackgroundScroller` 부착 + 속도 값 | **씬 — Codex** |

### ⬜ 정할 것

1. **이동 구간 길이** — 몇 초인가. 12연차를 도는 게임이라 **매 연차 반복된다.**
   길면 지겹고 짧으면 안 보인다. 스킵 가능해야 하는지도
2. **걷는 표현이 있는가** — 지금 유닛 스프라이트에 걷기 프레임이 있는지 확인해야 한다.
   없으면 위아래로 까딱이는 정도로 대체(아트 추가 없이 가능)
3. **웨이브 전환(연차 안에서)에도 작은 연출을 주나** — 연차는 4번에 한 번뿐이라
   웨이브마다는 다른 처리가 필요할 수 있다
